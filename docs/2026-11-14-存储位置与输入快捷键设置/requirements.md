## 0. 与现有需求的关系

本需求补充两项可配置能力：

| 能力 | 当前行为 | 本需求目标 |
| --- | --- | --- |
| 附件存储位置 | 固定 `%APPDATA%\ScreenToAgent\attachments` | 用户可在设置中选择存储根目录 |
| 输入快捷键 | 截图输入 `Ctrl+Enter` 发送、`Esc` 退出；会话输入 `Enter` 发送、`Esc` 退出焦点 | 用户可分别设置发送与退出快捷键 |

不改变：

- 应用不管理 Agent 会话；CLI 历史仍只读，API 仍单轮。
- 截图输入退出后保留草稿（REQ-002 FR-13）。
- 会话界面只有截图热键可隐藏；`Esc` 不隐藏整个会话。
- 图片附件只用于展示与本次发送，不作为下一次请求的自动上下文。

## 1. 背景与问题

当前截图附件固定在 `%APPDATA%`，空间紧张或希望统一管理素材的用户无法选择其他磁盘/目录。输入框的发送与退出键也写死，不同键盘布局或操作习惯的用户难以调整。

本需求让用户能够：

1. 指定 ScreenToAgent 附件（截图）的存储根目录。
2. 为截图输入框和会话输入框分别设置发送快捷键与退出快捷键。

## 2. 目标与非目标

### 2.1 目标

- G1：设置页可选择附件存储根目录，并展示实际生效路径。
- G2：新截图/图片写入用户指定目录；路径无效或不可写时明确拒绝，不丢旧路径。
- G3：截图输入和会话输入可分别配置“发送”和“退出/失焦”快捷键。
- G4：快捷键冲突时明确提示并禁止保存。
- G5：设置持久化；默认值保持现有行为。
- G6：清理策略只作用于应用管理的附件目录，不影响用户其他文件。

### 2.2 非目标

- 不把配置文件本身或程序安装目录迁移到自定义位置。
- 不自动迁移已有附件；旧路径继续按原路径展示。
- 不改变全局截图热键的设置入口（仍在“截图快捷键”中）。
- 不允许把发送/退出快捷键设为与截图全局热键相同的组合（避免双重触发）。
- 不支持一条快捷键同时承担发送和退出。
- 不改变会话隐藏规则：输入框的退出快捷键只退出输入焦点，不隐藏会话界面。

## 4. 功能需求

### FR-1 自定义附件存储根目录（P0）

- 设置页新增“附件存储位置”：
  - 显示当前生效根目录。
  - 提供“浏览…”选择目录。
  - 提供“打开目录”与“恢复默认”。
- 默认根目录：`%APPDATA%\ScreenToAgent`；实际附件目录为 `<根目录>\attachments`。
- 新截图/图片写入 `<根目录>\attachments\<sha256>.png`；内容寻址规则不变。
- 存储路径使用绝对路径；支持包含空格与中文字符的本地路径。
- 路径变更只影响后续新附件；已有附件不自动移动或删除。
- 旧附件仍按其历史绝对路径显示；旧路径失效时仍显示“图片不可用”。
- 配置写入 `storage.root`，只保存路径，不保存图片内容。
- 目录变更后，设置页立即展示实际生效路径；新请求使用新目录。

### FR-2 存储路径校验与失败处理（P0）

- 保存前必须验证：
  - 路径可创建（不存在时尝试创建 `<根目录>\attachments`）。
  - 可写入探针文件并删除。
  - 路径不是程序安装目录、不是只读目录、不是明显的系统保护目录。
- 校验失败时：
  - 明确提示失败原因。
  - 禁止保存，保留旧路径与旧配置。
  - 不丢失已选路径文本，便于用户修改。
- 应用启动时若配置路径不可用：
  - 回退到默认 `%APPDATA%\ScreenToAgent`。
  - 托盘/设置页提示“存储路径不可用，已回退默认路径”。
  - 不自动删除旧目录内容。
- 网络盘/可移动盘允许选择，但设置页提示“设备不可用时截图可能失败”；不保证设备始终在线。
- 不支持相对路径与空路径。

### FR-3 清理与迁移边界（P1）

- 自动清理只作用于当前配置的 `<根目录>\attachments`。
- 只删除符合应用内容寻址命名规则（64 位十六进制 + `.png`）的文件；不递归删除其他文件/目录。
- 旧根目录的附件在切换后不再参与自动清理；是否迁移由用户自行决定。
- 设置页可显示当前附件目录占用大小（P2）。
- 不提供自动迁移旧附件（避免破坏 CLI 历史中的绝对路径引用）；如后续需要，应单独评审迁移与路径重写。

### FR-4 输入快捷键设置（P0）

- 设置页新增“输入快捷键”分组，按输入场景分别配置：

| 场景 | 发送默认 | 退出默认 | 退出行为 |
| --- | --- | --- | --- |
| 截图标注输入 | `Ctrl+Enter` | `Esc` | 退出截图，保留问题草稿（REQ-002 FR-13） |
| 会话底部输入 | `Enter` | `Esc` | 仅让输入框失焦，不隐藏会话 |

- 每个快捷键支持组合键（如 `Ctrl+Enter`、`Alt+S`、`Shift+Enter`）；显示人类可读文本。
- 发送快捷键：
  - 触发发送当前输入；空内容不发送。
  - 不插入换行。
- 退出快捷键：
  - 截图场景：关闭截图输入并保留草稿。
  - 会话场景：输入框失焦；消息、草稿与会话保持可见。
- `Shift+Enter` 始终作为换行键，除非它被配置为发送键；不允许把 `Shift+Enter` 配置为发送键（与换行语义冲突）。
- 会话输入原有 `Enter` 发送、`Shift+Enter` 换行行为在默认配置下保持不变。
- 截图输入的快捷键在遮罩打开期间有效；会话输入快捷键在输入框获得焦点时有效。
- 快捷键修改后尽可能立即作用于已打开输入框；无法立即应用时，下一次打开输入框生效，并在设置页说明。

### FR-5 快捷键冲突校验（P0）

- 同一场景内发送键与退出键不得相同。
- 跨场景允许使用相同快捷键（例如截图退出与会话退出都用 `Esc`），因为两个输入面不会同时存在。
- 输入快捷键不得与截图全局热键相同。
- 保存前必须校验；冲突时明确提示具体冲突对象，并禁止保存。
- 不得静默覆盖旧快捷键。
- 快捷键可为空吗？不允许；清空即校验失败。
- 若系统/其他程序占用组合键，只在应用内冲突时阻止；实际使用失败时给出可操作提示。
- 恢复默认必须同时恢复两组输入快捷键，不影响截图全局热键。

### FR-6 设置持久化与生效（P0）

- 配置新增：
  - `storage.root`
  - `input_shortcuts.screenshot.send`
  - `input_shortcuts.screenshot.exit`
  - `input_shortcuts.conversation.send`
  - `input_shortcuts.conversation.exit`
- 默认值保持现有行为：
  - `storage.root` = 空/默认 APPDATA 路径
  - 截图发送 `Ctrl+Return`，退出 `Esc`
  - 会话发送 `Return`，退出 `Esc`
- 保存后写入 `%APPDATA%\ScreenToAgent\config.json`；不需要重启。
- 路径或快捷键保存失败时，旧配置保持有效。
- 设置页“恢复默认”需二次确认，并同时恢复路径与输入快捷键（若用户选择）。
- 修改输入快捷键后，托盘/会话界面无额外提示，不打断当前生成。

### FR-7 与截图草稿、会话状态的兼容（P0）

- 截图输入退出快捷键与全局截图热键均触发“退出并保留草稿”；两者可同时存在。
- 会话输入退出快捷键只失焦，不改变会话可见性；再次点击输入框可继续编辑。
- 发送快捷键发送后：
  - 截图草稿清空；
  - 会话输入清空；
  - 会话保持原可见性；
  - 不显示“正在生成”提示。
- 修改存储路径不影响已打开会话中的历史图片引用。
- 生成回答期间修改设置：允许打开设置，但输入快捷键与存储路径变更应在下一轮生效；不得中断流式输出。

## 5. 交互流程

### 5.1 修改存储位置

1. 用户打开托盘“设置…”。
2. 点击“附件存储位置”的“浏览…”，选择 D:\ScreenToAgentData。
3. 应用校验并创建 `D:\ScreenToAgentData\attachments`。
4. 保存后设置页显示实际路径；下一次截图写入该目录。
5. 旧 `%APPDATA%\ScreenToAgent\attachments` 保持不变，历史仍可显示。

### 5.2 修改输入快捷键

1. 在设置页“输入快捷键”中修改截图发送键为 `Alt+S`。
2. 设置页检测是否与退出键、其他输入键或截图热键冲突。
3. 无冲突则保存；下一次截图标注输入使用 `Alt+S` 发送。
4. 若冲突，显示“与截图热键/退出键冲突”，禁止保存。

### 5.3 退出输入

- 截图输入：按退出快捷键 → 关闭截图，保留草稿；下次框选回填。
- 会话输入：按退出快捷键 → 输入框失焦，会话仍可见，草稿保留；点击输入框继续。

## 6. 配置示例

```json
{
  "storage": {
    "root": "D:\\ScreenToAgentData"
  },
  "input_shortcuts": {
    "screenshot": {
      "send": "Ctrl+Return",
      "exit": "Esc"
    },
    "conversation": {
      "send": "Return",
      "exit": "Esc"
    }
  }
}
```

说明：

- `storage.root` 为空时使用默认 APPDATA 根目录。
- 实际附件目录始终为 `<root>\attachments`。
- 快捷键使用 Qt 可解析的字符串；保存前统一规范化。

## 8. 验收标准

- AC-01：设置页可修改附件存储根目录；保存后新截图写入 `<root>\attachments`。
- AC-02：无效/不可写路径保存失败并提示原因，旧路径与旧配置保持不变。
- AC-03：切换存储路径后旧附件不被移动或删除，旧历史图片仍按原路径显示。
- AC-04：清理仅删除应用内容寻址命名的附件，不删除目录中其他文件。
- AC-05：应用重启后存储路径保持；路径不可用时回退默认并提示。
- AC-06：截图输入可修改发送/退出快捷键，默认仍为 `Ctrl+Enter` / `Esc`。
- AC-07：会话输入可修改发送/退出快捷键，默认仍为 `Enter` / `Esc`。
- AC-08：同一场景发送键与退出键相同、或任一输入键与截图全局热键相同，均被提示并禁止保存；跨场景同键（如 Esc）允许。
- AC-09：截图输入按退出快捷键会关闭截图并保留草稿，下次框选回填。
- AC-10：会话输入按退出快捷键只失焦，会话保持可见，草稿不丢。
- AC-11：发送快捷键发送后不插入换行；`Shift+Enter` 默认仍换行。
- AC-12：恢复默认同时恢复路径与两组快捷键，不影响截图全局热键。
- AC-13：设置保存后无需重启生效；配置中只保存路径与快捷键，不保存图片/问答内容。

## 11. 当前实现说明（0.2）

已实现：

- 设置页包含截图热键、附件存储位置、四组输入快捷键。
- 存储根目录保存到 `storage.root`，实际使用 `<root>\attachments`；默认 `%APPDATA%\ScreenToAgent`。
- 保存时创建目录并写探针文件校验；失败保持旧路径；启动时路径不可用会回退默认并提示。
- 新附件写入新目录；旧附件不迁移；清理只作用于当前附件目录的应用命名文件。
- 截图输入发送/退出、会话输入发送/退出均可配置；默认保持 `Ctrl+Enter` / `Esc` / `Enter` / `Esc`。
- 截图退出保留草稿；会话退出只让输入框失焦，不隐藏会话。
- 同场景发送/退出冲突、与截图热键冲突、`Shift+Enter` 发送均被阻止；跨场景同键允许。
- 设置保存到 `config.json` 并即时应用；恢复默认仅恢复存储与输入快捷键，不改截图热键。

当前限制：

- 日志目录仍固定在 `%APPDATA%\ScreenToAgent\logs`，不在本需求 P0 范围。
- 不自动迁移旧附件。
- 网络盘/移动盘只做风险提示，无法保证离线时可用。
- 系统级快捷键被其他程序占用时无法提前探测，只能在使用失败时提示。
