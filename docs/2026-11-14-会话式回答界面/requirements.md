## 1. 背景与问题

当前原型是单次问答：截图、提问、等待、通知、看一次回答。回答层关闭后，用户无法在同一个界面继续追问，也无法查看之前的回答。用户希望把它变成“像聊天一样”的会话界面，但仍然坚持：会话和上下文由 Codex CLI 管理，工具不自己维护 Agent 会话。

同时，发送问题后出现的“正在生成”状态层被认为是干扰，用户希望发送后界面保持安静，只在会话隐藏且回答完成时于右下角提示。

## 2. 目标与非目标

### 2.1 目标

- G1：发送问题后，界面中不出现生成状态、加载动画、弹窗或其它提示。
- G2：会话界面隐藏时，回答完成后在 Windows 右下角弹出“回答完成”通知；会话界面可见时直接在界面内展示回答，不弹通知。
- G3：快捷键打开全屏半透明会话界面；再次按快捷键仅隐藏界面，不销毁会话。
- G4：会话界面支持历史上下滚动，并在底部提供输入栏；用户可在界面内继续向 Agent 提问。
- G5：隐藏后再次打开，恢复之前的会话内容、当前会话和输入草稿，并展示期间新增的问答。
- G6：支持 `/new`、`/resume`、`/rename` 会话命令，并将其映射到 Codex CLI 实际提供的会话能力；支持选择历史会话。
- G7：应用仍不拥有 Agent 会话和上下文；会话、历史与续接由 CLI 管理，应用只负责输入、展示与命令转发。
- G8：在会话存在后，仍提供明确的截图提问入口，避免与“快捷键开关会话”冲突。
- G9：默认沿用旧会话；只有用户主动 `/new` 才新建会话，`/resume` 用于切换；后续截图与文字提问都发送到当前会话。
- G10：按住快捷键进入截图框选；快速轻点且未选择截图范围时显示/切换会话界面，不进入截图。

### 2.2 非目标

- 不做完整的终端模拟器，不内嵌 Codex 交互式 TUI。
- 不建立本地会话数据库，不持久化问答内容，不用本地记录拼接上下文。
- 不伪造 CLI 不支持的会话命令；例如 CLI 不支持重命名时，`/rename` 必须明确报不支持。
- API Key 模式不提供跨请求会话与历史；该模式的限制见 FR-11。
- 不做多用户、云同步、多窗口会话。
- 不在生成期间显示任何“正在生成”提示；仅提供会话隐藏时的完成/失败通知，界面可见时在界面内更新。

## 4. 功能需求

优先级定义：P0 为本次必须；P1 为本次应具备；P2 为后续增强。

### FR-1 发送后界面保持安静（P0）

- 无论从截图标注发送，还是从会话输入栏发送，发送动作完成后必须立即关闭截图遮罩/标注输入。
- 发送后不得显示以下任何内容：
  - “正在生成”状态层、加载动画、进度条。
  - 发送成功提示、Toast、模态框、任务栏闪烁等额外交互提示。
  - 自动打开或切换到会话界面。
- 允许保留托盘图标本身；不得通过气泡提示“已发送”或“正在回答”。
- 生成期间用户按快捷键时，打开会话界面（若已有会话），界面内也不显示独立的“生成中”提示；只保留已发送的问题消息。
- 回答完成或失败时，按 FR-2 通知。

### FR-2 回答完成通知（P0）

- **会话界面隐藏时**：请求完成时在 Windows 右下角弹出系统通知，标题或正文包含“回答完成”；请求失败时通知“回答失败”。
- **会话界面可见时**：回答完成直接在历史区域追加 Agent 回答，失败直接追加错误消息；不得再弹右下角通知，避免重复打扰。
- 取消的请求不发送完成通知。
- 点击隐藏状态下的“回答完成”通知打开会话界面，并定位到本次回答开头；点击失败通知定位到错误信息。
- 通知正文不得包含回答内容、提问内容或截图信息。
- 通知应使用系统托盘/Windows 通知区域，不从屏幕中央弹窗。
- Windows 通知被专注助手抑制时，托盘图标应至少能体现“有待查看回答”的状态。

### FR-3 全屏半透明会话界面（P0）

- 会话界面为全屏、无边框、置顶窗口，覆盖鼠标所在屏幕；背景半透明，可看到后方内容。
- 界面从上到下包含：
  1. 顶部会话信息栏：当前会话名称/标识、后端类型（Codex CLI / API）、关闭提示。
  2. 中部历史区域：按时间顺序展示用户问题、Agent 回答、系统/错误信息。
  3. 底部输入栏：多行输入、发送按钮、截图提问按钮、命令提示。
- 会话界面只允许通过用户再次按截图快捷键隐藏；`Esc` 不隐藏整个会话界面，只能关闭会话选择器/命令面板或退出输入焦点。
- 界面打开期间不阻止全局快捷键。
- 同一时间只允许存在一个会话界面实例。
- 打开时：
  - 若刚完成一次回答，定位到本次回答的第一个字符。
  - 若用户手动打开，默认定位到最近一次回答的开头；若期间没有新回答，恢复上次阅读位置。
- 会话界面不展示独立聊天侧栏或会话列表；会话选择通过 `/resume` 完成。

### FR-4 历史问答查看（P0）

- 历史区域支持鼠标滚轮上下滚动，支持 `PageUp`/`PageDown`、拖动滚动条。
- 输入框获得焦点时，`↑`/`↓` 用于文本光标移动；历史滚动使用 `PageUp`/`PageDown` 或滚轮。
- 历史消息按时间顺序展示；用户问题与 Agent 回答有明显视觉区分。
- 截图提问在历史中可显示问题文本（截图缩略图 P1，可选）。
- CLI 模式：
  - 打开会话或执行 `/resume` 时，优先通过 Codex CLI 提供的会话历史接口读取该会话历史。
  - 应用可以在内存中缓存当前会话消息用于渲染，但不得写入本地历史库，也不得用缓存拼接下一次请求的上下文。
  - 若 CLI 无法读取历史，显示系统提示“无法从 CLI 读取完整历史”，并展示当前进程内的消息。
- API 模式：历史仅限当前进程内存；应用重启后不可恢复。
- 历史较长时不得阻塞 UI；采用分批加载/懒加载，滚动过程中保持流畅。
- 会话内容不得被写入日志或临时文件。

### FR-5 底部输入栏与继续提问（P0）

- 会话界面底部始终显示输入栏；输入栏支持多行文本、中文输入法。
- `Enter` 发送，`Shift+Enter` 换行；空输入不发送。
- 用户发送普通文本后：
  - 该文本作为用户消息追加到历史区域。
  - 请求发送到当前会话；回答完成后追加为 Agent 消息。
  - 不出现任何独立的“正在生成”提示。
- 生成期间输入栏可编辑，但发送按钮禁用或发送动作被忽略；不得弹出提示解释。回答完成后自动恢复。
- 同一会话同一时间只允许一个进行中的回答；不允许并行发送。
- 输入草稿在隐藏/恢复会话时保留。
- 输入框为空且历史区域可滚动时，滚轮/`PageUp`/`PageDown` 控制历史滚动。
- 发送截图问题也走同一消息列表，作为带截图标记的用户消息。

### FR-6 截图快捷键：长按截图、轻点会话（P0）

截图快捷键采用“长按/轻点”区分：

| 操作/状态 | 行为 |
| --- | --- |
| 轻点（按下后约 250ms 内松开），且未选择截图范围 | 显示/切换会话界面；没有会话时打开空会话界面，不进入截图。 |
| 按住约 250ms 以上 | 进入截图模式，显示遮罩并可用鼠标框选范围；会话可见时先隐藏会话。 |
| 已进入截图框选 | 松开快捷键不取消截图；用户可继续框选，`Esc` 取消。 |
| 正在框选或标注时再次按键 | 忽略，不打断当前截图。 |
| 正在生成回答时轻点 | 显示/隐藏会话；不显示生成状态。 |
| 正在生成回答时按住 | 不启动新截图；松开后按轻点处理。 |
| 设置或会话选择器打开 | 忽略截图快捷键。 |

- 轻点不得让截图遮罩闪现；只有达到长按阈值才进入截图。
- 长按进入截图后，发送问题保持安静，不自动弹出会话；回答完成时按 FR-2 通知。
- 截图入口包括：
  - 按住截图快捷键后框选。
  - 会话界面输入栏的“截图提问”按钮。
  - 托盘菜单“截屏提问”。
- 从会话界面按钮或托盘进入截图时，先隐藏会话，再进入框选；发送后不自动打开会话。
- 不再需要第二个截图快捷键；如后续增加独立截图热键，另行评审。
- 截图提问始终发送到当前会话：默认沿用旧会话；执行 `/new` 后发送到新会话；执行 `/resume` 后发送到所选会话。
- 会话仅由轻点快捷键或托盘“隐藏会话”隐藏；`Esc` 不隐藏整个会话。

### FR-7 会话命令（P0）

输入栏支持以 `/` 开头的会话命令。命令只在输入框开头识别，执行后不作为问题发送给 Agent。

| 命令 | 行为 | 后端范围 |
| --- | --- | --- |
| `/new` | 新建会话：CLI 模式新建 CLI 会话并清空当前界面消息；后续文字与截图提问都进入新会话。API 模式清空当前界面并开始新的单轮请求序列。 | CLI、API |
| `/resume` | 打开会话选择器，列出可恢复的 CLI 会话；选择后加载该会话历史并设为当前会话；后续文字与截图提问进入所选会话。 | 仅 CLI |
| `/resume <id\|name>` | 直接按 Codex CLI 支持的会话 id 或名称恢复；失败时保持当前会话不变。 | 仅 CLI |
| `/rename <new-name>` | 调用 Codex CLI 提供的会话重命名能力；成功后更新会话标题。 | 仅 CLI |
| 未知命令 | 在界面内显示命令帮助，不发送给 Agent。 | 全部 |

- `/new` 和 `/resume` 在执行前必须检查当前是否正在生成；生成中执行时显示行内系统消息，不改变会话。
- `/resume` 无参数时应打开会话选择器；选择器数据必须来自 Codex CLI 的会话列表/浏览能力，不允许应用自行编造会话。
- 会话选择器展示：名称/标识、最近更新时间、工作目录（若 CLI 提供）；支持键盘与鼠标选择，`Esc` 关闭选择器但不关闭会话界面。
- `/rename` 必须映射到 CLI 的真实能力。若当前 Codex CLI 版本不提供重命名接口，必须提示“当前 Codex CLI 不支持重命名会话”，禁止只在本地改名。
- 命令执行结果以系统消息显示，例如“已切换到会话 xxx”“已新建会话”“CLI 不支持重命名”。
- 命令失败时不得清空当前消息列表或切换会话。
- API 模式下 `/resume`、`/rename` 提示“API 模式不保留历史会话”，不执行。

### FR-8 会话选择与当前会话（P0）

- 默认会话规则：
  - 应用启动或尚无当前会话引用时，默认沿用 Codex CLI 的旧会话（CLI 的最近会话）；不得自动执行新建。
  - 只有用户主动输入 `/new` 才建立新会话；之后文字提问与截图提问都进入该新会话。
  - `/resume` 切换到所选会话后，之后文字提问与截图提问都进入所选会话。
  - 若 CLI 中没有任何可续会话，首条消息才创建新会话。
- CLI 模式维护一个“当前会话引用”（仅 id/name，保存在内存中，不保存问答内容）。
- `/new` 后当前会话引用指向新会话；第一条消息创建/绑定该会话。
- `/resume` 选中会话后，当前引用更新，历史替换为所选会话历史，后续消息继续该会话。
- 应用重启后：
  - CLI 模式默认再次沿用 CLI 的最近会话；也可通过 `/resume` 选择其他会话；不得使用应用自存历史恢复。
  - API 模式没有可恢复会话。
- 会话引用与历史缓存不得写入本地数据库；配置文件中也不保存问答内容。
- 选择会话失败时，保持原会话和原消息列表不变，并显示错误。
- 会话名称/标识以 CLI 返回为准；应用不另行生成会话名称。

### FR-9 隐藏、恢复与生命周期（P0）

- 隐藏会话只改变可见性，不取消正在进行的请求、不清空消息、不重置输入草稿。
- 隐藏期间完成回答时：
  - 按 FR-2 发送“回答完成”通知（此时界面隐藏）。
  - 回答追加到会话历史。
  - 再次打开时展示新增回答，并定位到其开头。
- 会话界面可见时完成回答：只把回答追加到历史，不弹右下角通知；失败时同理只追加错误消息。
- 再次打开时恢复：
  - 当前会话引用。
  - 消息列表。
  - 输入草稿。
  - 若无新回答，恢复上次阅读位置；若有新回答，定位到新回答开头。
- 应用退出后会话界面与内存消息消失；CLI 会话仍由 CLI 保留，API 会话无法恢复。
- 隐藏会话不等于取消请求；取消操作见 FR-10。
- 快捷键快速重复按下不得创建多个会话窗口或重复请求。

### FR-10 失败、取消与命令错误（P0）

- 会话界面隐藏时，回答失败在右下角通知“回答失败”；会话界面可见时只在会话历史中追加错误消息，不弹通知；两种情况都不弹出模态框。
- 提供取消当前回答的入口（托盘菜单“取消当前回答”或会话界面内非提示性操作）；取消不发送“回答完成”通知。
- 取消后输入栏恢复可用，当前用户消息保留，追加“已取消”系统消息。
- `/new`、`/resume`、`/rename` 失败时只追加系统错误消息，不破坏当前会话。
- 历史加载失败时保留当前可见消息，并显示失败原因；不得阻止用户继续输入。
- 所有错误信息不得包含 API Key、完整命令行或敏感路径。

### FR-11 API 模式边界（P0）

- API Key 模式仍是单轮、无上下文；会话界面中的历史仅用于展示，不发送给 API。
- `/new`：清空当前界面消息，后续请求仍是独立单轮。
- `/resume`、`/rename`：不可用，显示明确提示。
- 应用重启后不保留 API 会话历史。
- 通知、输入栏、隐藏/恢复行为与 CLI 模式一致，但历史来源不同。

### FR-12 长按截图与轻点会话（P0）

- 截图快捷键采用按下/释放时长区分意图，默认长按阈值为 250ms。
- **轻点**：按下后在阈值内释放，且没有进入截图框选时：
  - 若会话界面可见：隐藏会话。
  - 若会话界面隐藏：显示会话，恢复历史、草稿与阅读位置。
  - 若尚无会话：打开空会话界面（当前会话为“新会话”，可直接输入或使用会话命令）。
  - 轻点不得让截图遮罩闪现。
- **长按**：按住达到阈值后进入截图模式：
  - 先隐藏会话界面（如可见），再冻结屏幕并显示框选遮罩。
  - 用户可用鼠标选择区域；允许在松开快捷键后继续框选。
  - 松开快捷键不会取消已开始的截图；`Esc` 取消。
  - 长按进入截图后，本次按键释放不得再当作轻点处理去打开会话。
- 在截图/标注进行中再次按键忽略；在生成回答期间：
  - 轻点只切换会话界面显示状态。
  - 长按不启动新的截图，松开后按轻点处理。
- 设置或会话选择器打开时忽略截图快捷键。
- 长按阈值不提供 UI 提示，避免干扰；阈值可在后续版本考虑配置。
- 截图范围仍由既有截图遮罩与标注逻辑完成；本需求只改变触发方式。

### FR-13 截图输入草稿与快捷键退出（P0）

- 在截图标注输入框中，`Ctrl+Enter` 发送当前问题；工具栏“发送”等价。
- 截图或标注进行中再次按截图快捷键：退出当前截图输入，不发送任何内容。
- 退出时保留当前输入框中的问题文本；即使尚未框选（输入框未出现），也保留此前草稿。
- 下一次进入截图并在选区完成后，输入框自动回填保留的草稿，光标位于文本末尾，可继续编辑。
- 同一次截图流程中点击“重新框选”时，已输入文本也必须保留并在新选区输入框中恢复。
- 发送成功后清空草稿；下一次截图输入为空，不重复回填已发送的问题。
- `Esc` 或“取消”等非发送退出同样保留草稿；用户不会因误退出丢失输入。
- 快捷键退出只退出截图输入，不自动打开会话界面；该次按键释放不当作轻点处理。
- 草稿仅保存在内存中；应用退出后清空，不写入配置或日志。
- 草稿与截图图像分离：退出后丢弃本次截图，只保留问题文本。

## 5. 交互流程

### 5.1 截图发送到完成

1. 用户通过会话界面“截图提问”或托盘“截屏提问”发起截图。
2. 会话界面隐藏，进入框选与标注。
3. 用户发送问题；截图界面关闭，不显示任何生成提示，也不自动打开会话。
4. Agent 完成后，因为会话界面处于隐藏状态，右下角通知“回答完成”。
5. 用户按快捷键打开会话界面，看到该问题与回答；历史可向上滚动。

### 5.2 会话内继续提问

1. 用户按快捷键打开会话界面。
2. 在底部输入栏输入问题并回车。
3. 用户消息立即追加，输入栏禁用发送；不显示生成提示。
4. 回答完成后追加到历史；因为会话界面可见，不弹右下角通知。
5. 用户可继续输入；再次按快捷键隐藏界面。

### 5.3 隐藏与恢复

```text
会话可见 ──快捷键──> 会话隐藏（请求继续运行）
   ^                       │
   │                    完成通知
   └──────快捷键───────────┘
```

- 隐藏期间新回答只追加到内存会话并通知。
- 会话可见期间新回答只追加到界面，不弹通知。
- 再次打开时如果有新回答，定位到新回答开头；否则恢复上次阅读位置。

### 5.4 会话命令

```text
用户输入 /resume
  -> 打开 CLI 会话选择器
  -> 读取 CLI 会话列表
  -> 选择会话
  -> 加载该会话历史并设为当前会话
  -> 后续文字与截图提问继续该会话
```

`/new`、`/resume`、`/rename` 的具体 CLI 参数由实现阶段核对；应用不能自行模拟这些能力。

## 7. 数据与配置

- 不新增本地会话/问答数据库。
- 内存状态：
  - 当前会话引用（CLI 返回的 id/name；应用启动时默认解析为 CLI 最近会话）。
  - 当前界面消息列表（仅展示缓存）。
  - 输入草稿、滚动位置、可见性。
- 上述内存状态不写入配置文件；应用退出即丢弃。
- 配置文件只允许保存 UI 偏好（如通知开关、回答层不透明度、快捷键），不得保存问答内容。
- CLI 模式的历史、会话列表、重命名结果均以 CLI 返回为准。
- API 模式没有会话引用与历史来源。

### 7.1 命令映射

| 命令 | 设计映射 | 备注 |
| --- | --- | --- |
| `/new` | 新建 CLI 会话（不带 resume） | 清空当前界面消息，首条消息绑定新会话；后续截图与输入进入新会话。 |
| `/resume` | CLI 会话列表 + 按 id/name resume | 实现从 Codex CLI 的 rollout 会话文件只读读取列表与历史；不能自造会话。 |
| `/rename <name>` | CLI 的会话重命名能力 | 当前 Codex CLI 0.165 未提供命令行重命名能力，明确提示不支持，不在本地伪造。 |

## 8. 验收标准

- AC-01：从截图或输入栏发送后，界面中不出现生成状态层、加载动画、Toast 或“正在生成”文案。
- AC-02：会话界面隐藏时，回答完成后 Windows 右下角出现“回答完成”通知；会话界面可见时只在界面内追加回答，不弹通知。
- AC-03：按快捷键打开会话界面，能看到历史问题与回答，底部有输入栏。
- AC-04：会话界面可见时按快捷键只隐藏，不销毁会话；再次按快捷键恢复相同会话。
- AC-05：隐藏期间完成的回答会追加到会话；恢复后能看到新回答，并在打开时收到完成通知。
- AC-06：在输入栏发送普通问题，用户消息与 Agent 回答都出现在同一会话界面中，且没有额外提示。
- AC-07：历史区域支持滚轮、`PageUp`/`PageDown` 滚动；打开时定位到最新回答开头或恢复原阅读位置。
- AC-08：`/new` 清空当前界面并开始新的 CLI 会话；之后文字提问与截图提问都进入新会话。
- AC-09：`/resume` 能列出 CLI 会话（或按 CLI 支持的方式输入 id/name），选择后加载对应历史并继续该会话；之后文字与截图提问都进入所选会话。
- AC-10：`/rename <name>` 调用 CLI 能力成功时更新会话名；CLI 不支持时明确提示，不在本地伪造改名。
- AC-11：API 模式下 `/resume`、`/rename` 显示不可用提示；历史不跨请求、不跨重启。
- AC-12：应用退出后没有新增本地会话数据库或问答文件；历史只能从 CLI 或内存获得。
- AC-13：`Esc` 不隐藏会话界面；只有快捷键能隐藏。
- AC-14：从会话界面发起截图后，发送完成不自动弹出会话；完成通知仍正常出现。
- AC-15：生成期间隐藏会话不会取消请求；完成通知和后续历史仍正确。
- AC-16：会话界面、截图界面、设置界面不会同时出现遮挡；重复按快捷键不产生多个会话窗口。
- AC-17：会话命令失败时不切换会话、不丢失当前消息，并显示行内错误。
- AC-18：长历史滚动不阻塞 UI，输入和通知仍可用。
- AC-19：应用启动后的首次请求默认沿用旧 CLI 会话，不自动新建；只有主动 `/new` 才建立新会话。
- AC-20：会话界面可见时完成回答，不出现右下角通知，只在历史区域追加回答。
- AC-21：`/new` 或 `/resume` 后的下一次截图提问分别进入新会话或所选会话，而不是旧会话。
- AC-22：轻点截图快捷键（阈值内按下并释放）且没有选择截图范围时，显示/切换会话界面，截图遮罩不闪现。
- AC-23：按住截图快捷键达到 250ms 后出现截图遮罩，可用鼠标框选；松开快捷键不取消截图。
- AC-24：会话界面可见时轻点快捷键隐藏；再次轻点恢复同一会话。
- AC-25：尚无会话时轻点快捷键打开空会话界面，可以直接输入问题。
- AC-26：长按进入截图后松开快捷键，不会误打开会话界面；截图仍可继续框选或 Esc 取消。
- AC-27：设置/会话选择器打开或正在框选/标注时，快捷键不会触发轻点会话或新的截图。
- AC-28：截图标注输入框中按 `Ctrl+Enter` 发送当前问题；发送成功后草稿清空。
- AC-29：截图/标注中再次按快捷键退出且不发送；已输入问题被保留，不自动打开会话。
- AC-30：下一次截图框选完成后，输入框自动回填上次保留的草稿，光标在末尾。
- AC-31：重新框选、Esc 或取消退出均保留当前草稿；发送后下一次不再回填已发送内容。

## 9. 风险与开放问题

| 编号 | 风险/问题 | 处理建议 |
| --- | --- | --- |
| R-1 | 会话存在后快捷键用于开关会话，无法再用同一个键直接截图 | 本需求采用“会话内截图按钮 + 托盘截屏”作为新入口；是否增加独立截图热键需另行确认。 |
| R-2 | Codex CLI 的会话列表、历史读取、重命名能力与版本相关 | 实现前核对当前 CLI；能力检测；不支持时明确提示，不模拟。 |
| R-3 | `/resume` 可能只有交互式 picker，缺少机器可读列表 | 评估 `codex agents`/app-server 或 CLI 只读接口；否则提供 id/name 输入兜底。 |
| R-4 | 历史格式与消息边界解析复杂 | 优先使用 CLI 结构化接口；失败时降级为进程内消息并提示。 |
| R-5 | 默认沿用 CLI 最近会话，可能续接到用户在其他终端使用的会话 | 顶部明确显示当前会话标识；用户可随时 `/new` 或 `/resume` 切换。 |
| R-6 | 仅允许快捷键隐藏，`Esc` 无效可能造成操作习惯冲突 | 按用户要求执行；在顶部显示“快捷键隐藏”提示。 |
| R-7 | API 模式无历史，用户可能误解 | 在顶部与命令反馈中明确“API 单轮、无历史”。 |
| R-8 | 1000+ 消息的渲染内存与滚动性能 | 分批加载、限制内存缓存、避免重复 Markdown 解析。 |
| R-9 | “旧会话”的精确含义可能与 CLI 最近会话不同 | 默认按 CLI 最近会话实现；在界面显示当前会话，并提供 `/resume` 切换。 |
| R-10 | 历史/列表依赖 Codex CLI 内部 rollout 文件格式 | 适配器隔离读取逻辑；升级 CLI 后回归验证；解析失败时降级为进程内消息并提示。 |
| R-11 | 长按阈值过短可能误触截图，过长可能让轻点会话反应迟滞 | 默认 250ms；文案中说明“按住约 250ms 后框选”；后续可考虑可配置。 |
| Q-1 | 会话存在后如何发起新截图？ | 建议采用“会话内截图按钮 + 托盘截屏”；是否增加第二个截图热键待确认。 |
| Q-2 | `/resume` 是否必须提供可视化选择器，还是允许输入会话 id/name？ | 已实现：优先可视化选择器，同时支持 `/resume <id|name>`。 |
| Q-3 | 当前 Codex CLI 是否支持会话重命名？ | 已确认 0.165 未提供命令行重命名；`/rename` 明确报错，不本地改名。 |
| Q-4 | 会话界面可见时是否仍需右下角通知？ | 已确认不需要；只在界面内追加回答。 |
| Q-5 | 应用重启后 CLI 会话恢复到最近会话还是打开选择器？ | 已确认默认沿用旧会话（CLI 最近会话）；`/resume` 可切换。 |
| Q-6 | Esc 是否作为紧急关闭入口？ | 按需求仅快捷键隐藏；若可用性测试反馈强烈，再评审。 |
| Q-7 | “默认沿用旧会话”是否等于 CLI 的最近会话？ | 实现为 CLI 最近会话；若该语义不符合预期，需明确“上次本工具使用的会话”是否允许由应用记住引用。 |
| Q-8 | 长按阈值 250ms 是否合适？是否需要设置项？ | 实现先固定 250ms；根据实际手感再决定是否提供配置。 |

## 11. 当前实现说明（0.5）

- 会话界面已替换原全屏回答层：历史、底部输入、会话信息、截图入口、`/new` `/resume` `/rename` 命令入口。
- 发送问题后不显示生成状态层/加载提示；回答完成时仅当会话界面隐藏才弹“回答完成”，界面可见时只在历史区域追加。
- 默认会话为 Codex CLI 最近会话；`/new` 只标记下一条请求创建新会话，之后的文字与截图都进入新会话；`/resume` 切换后同样进入所选会话。
- 历史与会话列表通过只读解析 Codex CLI 的 rollout 会话文件获得；应用不写入会话文件、不建立本地会话库，也不缓存为模型上下文。
- 截图快捷键改为长按/轻点：按住约 250ms 进入框选；阈值内轻点且未选择时显示/切换会话，无会话时打开空会话。
- 截图标注输入支持 `Ctrl+Enter` 发送；截图/标注中再按快捷键、Esc 或取消退出时保留问题草稿，下次框选后回填；发送后清空。
- `/rename` 当前明确不支持，原因见 Q-3。
- 已知限制：rollout 文件属于 CLI 内部格式，CLI 升级后可能需要更新解析适配器；解析失败时降级为当前进程内消息并提示。
