## 0. 与现有需求的关系

本需求在 REQ-002“会话式回答界面”的基础上增强三件事：

| 能力 | 当前实现 | 本需求目标 |
| --- | --- | --- |
| 模型 | 固定使用 Codex CLI 默认模型 | 会话界面可切换模型，后续请求使用所选模型 |
| 输出 | 等待完成后一次性展示回答 | 增量流式展示；API 使用 SSE，CLI 使用结构化 JSONL 流 |
| 历史图片 | 只展示问题文字，截图文件不显示 | 历史消息同时展示前期图片与文字，而不只是文件引用 |

不改变以下既有约束：

- 会话、上下文与历史仍由 Codex CLI 管理；应用不写会话文件、不建立问答数据库。
- 发送后不显示独立生成状态层；会话隐藏时才弹完成通知。
- `/new` 才新建会话，`/resume` 切换；后续截图与文字进入当前会话。
- 应用不伪造 CLI 不支持的会话能力。

## 1. 背景与问题

REQ-002 已经实现会话式界面，但仍有三个明显缺口：

1. 无法选择模型，用户必须在 Codex CLI 配置中修改默认模型。
2. 回答必须等全部生成完才出现，长回答等待感强；没有流式增量。
3. 历史只还原问题文字，截图/上传图片没有显示；用户看到的是文本，无法回看当时发给 Agent 的图片。

本需求让会话界面成为可切换模型、可流式阅读、可回看图文上下文的完整工作界面。

## 2. 目标与非目标

### 2.1 目标

- G1：会话界面显示当前模型，用户可切换；切换只影响后续请求，不改变进行中的请求。
- G2：回答按增量流式显示；API 使用 SSE，Codex CLI 使用其结构化 JSONL 事件流并统一映射为 UI 流事件。
- G3：流式期间不出现“正在生成”提示；会话隐藏时只在完成后通知。
- G4：历史消息同时展示图片与文字，并保持发送时的顺序；截图消息显示缩略图，而不是文件路径。
- G5：点击历史图片可预览原图；文件缺失时显示明确占位而不是空白。
- G6：图片缓存仅用于本地展示，不作为下一次请求的上下文自动重发；不建立问答数据库。

### 2.2 非目标

- 不做多模型并行对比或同时向多个模型提问。
- 不管理 Agent 会话；不将模型切换写入 CLI 会话文件或伪造会话状态。
- 不保证第三方 SSE 服务的所有扩展事件；只处理标准文本增量、完成与错误。
- 不把历史图片自动重新发送给模型；上下文仍由 CLI/API 语义决定。
- 不做云端图片同步或团队共享。

## 4. 功能需求

### FR-1 会话内模型切换（P0）

- 会话界面顶部显示当前模型名称与标识（slug）。
- 提供模型选择器，数据来源优先级：
  1. Codex CLI 的模型目录（CLI 模式，例如 `codex debug models` 返回的 catalog）。
  2. 配置文件中显式配置的模型列表。
  3. 手工输入模型 slug（选择器不可用时兜底）。
- CLI 模式切换模型后，下一次请求通过 `-m/--model <model>` 传给 `codex exec` / `codex exec resume`；不得修改用户的全局 Codex 配置。
- API 模式切换后，后续请求在请求体中携带所选 `model`。
- 模型切换只影响后续请求；正在流式输出的请求不得中途换模。
- 流式进行中模型选择器禁用；结束后恢复。
- 当前模型在本次运行期间保持；是否跨重启记住由配置决定（见 Q-1）。
- 模型不存在或调用失败时显示明确错误，保留当前会话与用户输入，不自动回退到其他模型。
- 若模型目录标明不支持图片输入，而当前消息包含截图/图片，发送前提示用户更换模型或取消；不得静默发送。
- 模型列表加载失败时允许手工输入模型 slug；不得阻塞会话界面打开。

### FR-2 流式输出（P0）

- API 后端优先使用 SSE（`text/event-stream`）读取增量；解析文本 delta、完成事件与错误事件。
- Codex CLI 后端使用其结构化输出（`--json` JSONL 事件）读取增量；适配器将事件统一映射为以下 UI 流事件：
  - `started`：本轮开始，绑定用户消息与占位 Agent 消息。
  - `delta`：增量文本。
  - `completed`：完成，携带最终文本与会话引用。
  - `failed`：错误，携带可读错误信息。
- 流式事件只在会话界面的同一条 Agent 消息中增量更新，不创建多条回答。
- 首个增量到达后立即渲染；不得等待全部完成后才显示。
- 流式期间不显示独立的“正在生成”状态层、加载动画或发送成功提示。
- 会话可见时，增量直接更新历史区域；用户可滚动阅读，自动滚动仅在用户停留在底部时启用。
- 会话隐藏时，流式内容仅缓存到内存；完成时按既有的“隐藏才通知”规则弹“回答完成”。重新打开后显示完整回答或当前增量。
- 完成事件只应用一次；最终文本与已显示增量不得重复。
- 后端不支持流式时允许回退为一次性输出，但必须在内部标记为回退，不得伪装成流式。
- 流式取消或错误时保留已收到的部分内容，并追加“已取消/失败”系统消息；不得把半截内容当作完成。
- 流式期间输入栏发送与模型切换禁用，截图按钮禁用；输入草稿保留。

### FR-3 图片与文字历史（P0）

- 会话消息支持附件模型：文本 + 图片列表（0..N），并保持发送顺序。
- 截图提问在历史中显示：
  - 截图缩略图。
  - 用户在图上标注的问题文本。
  - 发送时间/角色（可选）。
- 历史消息不得只显示文件路径、文件名或“已上传文件”占位；必须渲染实际图片缩略图。
- 图片加载来源优先级：
  1. CLI 会话历史中可访问的图片路径（只读）。
  2. 应用自己的本地附件缓存（见 FR-4）。
  3. 缺失占位：显示“图片不可用”，保留文字与消息位置。
- 图片与文字按发送顺序展示；支持多图消息。
- 点击缩略图打开预览（新窗口或会话内浮层），支持关闭；预览不得阻塞会话主界面。
- 若历史图片路径失效，不得静默隐藏该消息；显示占位并保留问题文字。
- Agent 回答中的远程图片默认不加载（遵守既有资源安全约束）；历史图片只允许本地文件。
- API 模式的历史图片仅在当前进程内存中可用；应用重启后不可恢复。

### FR-4 附件缓存（P0）

- 应用在发送截图/图片时，将图片副本保存到本地附件缓存，例如：
  `%APPDATA%\ScreenToAgent\attachments\<sha256>.<png|jpg>`
- 传给 CLI 的图片路径优先指向该缓存文件，使 CLI 历史中记录的是可持久访问的路径；请求结束不得删除缓存文件。
- 缓存只用于本地展示；不得自动作为下一次请求的上下文重新发送。
- 附件缓存与问答内容分离：不建立会话数据库，不保存问题/回答正文。
- 缓存需要有上限与清理策略（例如按总大小/天数），并提供设置项或自动清理；清理不得破坏 CLI 会话本身。
- 缓存文件不得记录到日志；不包含 API Key。
- 同一图片内容只保存一份（内容寻址）；重复发送可复用。
- 旧历史中已失效的临时路径显示占位，不尝试猜测或替换成其他图片。

### FR-5 流式与通知时序（P0）

- 发送后不产生任何独立提示。
- 流式进行中不通知；完成或失败时：
  - 会话隐藏：右下角通知“回答完成”或“回答失败”。
  - 会话可见：仅在界面内完成/失败；不弹通知。
- 会话隐藏期间完成，重新打开时定位到本次 Agent 消息开头；若仍在流式，定位到当前增量末尾或开头（实现需固定一种策略）。
- 模型切换、流式状态、图片加载不得改变“只有快捷键隐藏会话”的规则。

### FR-6 取消、失败与重试（P0）

- 流式期间可通过托盘“取消当前回答”取消；取消后：
  - 终止 SSE/CLI 进程。
  - 保留已接收的部分内容，标记“未完成”。
  - 发送按钮与模型选择器恢复可用；不发送完成通知。
- 流式错误（网络中断、SSE 解析失败、CLI 退出码非 0）：
  - 保留部分内容。
  - 追加可读错误消息。
  - 不切换当前会话；不自动换模型。
- 完成事件缺失但连接关闭时，按失败处理，不把半截内容标记完成。
- 重试不自动进行；由用户再次发送（可编辑输入）触发。

### FR-7 CLI / API 差异（P0）

| 能力 | Codex CLI | API |
| --- | --- | --- |
| 模型列表 | CLI 模型目录/配置/手输 | 配置列表/手输 |
| 模型请求参数 | `-m <model>` | 请求体 `model` |
| 流式 | `--json` JSONL 事件 | SSE |
| 历史图片 | CLI 路径 + 本地缓存 | 当前进程内存 |
| 历史跨重启 | 由 CLI 提供 | 不可恢复 |
| 模型切换范围 | 后续请求 | 后续请求 |

- CLI 流式事件格式变化时，适配器应降级为一次性最终输出并提示。
- API 不支持 SSE 时回退为普通响应；UI 不得显示流式光标。
- 两种后端都不得把历史图片作为隐藏上下文自动重发。

## 5. 交互流程

### 5.1 切换模型并流式提问

1. 用户打开会话界面，顶部显示当前模型。
2. 用户从模型选择器选择新模型；选择器显示名称与 slug。
3. 用户输入问题或发起截图提问。
4. 请求携带新模型；界面先追加用户消息（含图片缩略图与文字）。
5. 首个流式增量到达后，在一条 Agent 消息中持续更新。
6. 完成：会话隐藏则通知“回答完成”；可见则仅完成更新。
7. 模型选择器恢复可用。

### 5.2 查看历史图文

1. 用户打开会话或 `/resume` 加载历史。
2. 历史解析出用户消息的文字与图片引用。
3. 图片解析顺序：CLI 路径 → 本地附件缓存 → 缺失占位。
4. 会话界面显示缩略图与文字；点击缩略图打开预览。
5. 缺失图片显示“图片不可用”，问题文字仍保留。

### 5.3 隐藏期间的流式输出

```text
会话可见 ──轻点热键──> 会话隐藏（流式继续）
   ^                         │
   │                    完成/失败通知
   └────────轻点热键─────────┘
```

- 隐藏时无流式 UI 提示；内容继续写入内存缓存。
- 打开后看到当前增量或完整回答；若仍在流式，后续增量继续更新同一条消息。

## 6. 数据与配置

- 不新增本地会话/问答数据库。
- 附件缓存：
  - 路径：`%APPDATA%\ScreenToAgent\attachments\`。
  - 内容寻址文件名，避免重复存储。
  - 保留策略可配置（天数/总大小），默认建议 30 天或 1GB，取较小者。
  - 仅保存图片副本；不保存问答文本。
- 模型配置：
  - 默认模型（可选）。
  - 自定义模型列表（API 模式必需；CLI 模式可空，使用 CLI catalog）。
  - 当前会话模型仅内存保存；是否跨重启恢复见 Q-1。
- CLI 参数：模型通过 `-m/--model` 传递；流式通过 `--json` 或 CLI 支持的结构化事件参数传递；具体参数需在实现阶段核对当前 CLI 版本。
- SSE：使用 `httpx` 流式读取，按事件边界解析，支持取消与超时。

## 8. 验收标准

- AC-01：会话界面显示当前模型；从 CLI 模型目录选择其他模型后，下一次 CLI 请求携带 `-m`，当前会话不变。
- AC-02：API 模式切换模型后，下一次请求体使用新模型。
- AC-03：流式进行中模型选择器禁用；完成后恢复。
- AC-04：API 模式收到 SSE 增量后立即更新同一条 Agent 消息，不出现生成状态层。
- AC-05：CLI 模式使用 JSONL 结构化事件流时同样增量显示；不支持时回退一次性输出且不显示流式光标。
- AC-06：完成事件只应用一次，最终文本不重复；取消/错误保留部分内容并标记未完成。
- AC-07：会话隐藏期间完成才弹“回答完成”；可见时只更新界面。
- AC-08：历史截图消息显示实际缩略图 + 标注文字，而不是文件路径或文件名。
- AC-09：历史图片路径失效时显示“图片不可用”占位，问题文字仍显示。
- AC-10：点击图片可预览；预览关闭后会话内容与滚动位置不丢失。
- AC-11：附件缓存使用内容寻址且可清理；不新增问答数据库；图片不作为下一次请求的隐藏上下文。
- AC-12：模型不支持图片而消息包含图片时，发送前提示更换模型或取消。
- AC-13：现有“发送无提示、隐藏才通知、会话开关、`/new` `/resume`”行为不回归。
- AC-14：API 模式重启后无历史图片；CLI 模式可由 CLI 历史 + 附件缓存恢复。

## 9. 风险与开放问题

| 编号 | 风险/问题 | 处理建议 |
| --- | --- | --- |
| R-1 | Codex CLI JSONL 事件结构/字段随版本变化 | 适配器版本检测与降级；关键事件做单测。 |
| R-2 | 模型目录接口可能不可用或包含不可用模型 | 允许配置列表/手工 slug；调用失败明确提示。 |
| R-3 | CLI 历史中的图片路径可能已失效 | 发送时改为持久附件缓存路径；旧记录显示占位。 |
| R-4 | SSE 流中断/完成事件缺失 | 保留部分内容并按失败处理；不把半截内容标记完成。 |
| R-5 | 图片缓存占用磁盘/隐私风险 | 内容寻址 + 大小/天数上限 + 可清理；不入日志。 |
| R-6 | 模型能力与图片输入不匹配 | 依据模型目录能力提示；API 无法判断时提示风险。 |
| R-7 | 流式渲染与 Markdown/图片混合导致重排/卡顿 | 增量阶段用纯文本或轻量 Markdown，完成后再做完整渲染（可评估）。 |
| R-8 | 隐藏期间流式内容缺少通知时机 | 完成/失败统一按会话可见性决定通知。 |
| Q-1 | 当前模型是否跨应用重启记住？ | 建议内存保存；如需跨重启，写入配置 `last_model`，不写会话内容。 |
| Q-2 | 附件缓存默认保留策略？ | 建议 30 天或 1GB，取较小者；设置页可调整。 |
| Q-3 | 历史图片是内联缩略图还是点击预览？ | 缩略图内联 + 点击预览；多图网格。 |
| Q-4 | API 模式是否需要模型能力元数据？ | 配置可维护能力标记；否则发送前只提示风险。 |
