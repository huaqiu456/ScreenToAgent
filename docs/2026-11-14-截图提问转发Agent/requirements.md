## 1. 背景与问题

用户在电脑前遇到问题时，往往需要先截图、保存文件、切换到终端或网页、粘贴图片、再描述问题。这个流程打断心流，且容易丢失上下文。

现有工具存在断层：

- 截图工具只能截图，不能直接在图上写出问题并发送给 Agent。
- Agent 工具（Codex CLI、其他命令行 Agent、在线 API）需要用户手动准备图片和文字。
- 本地 Agent 能力强且可离线使用，但入口不够轻量。
- 回答生成后，用户切换窗口查看会离开当前工作现场。

本项目要提供一款 Windows 常驻工具：通过全局热键 **F1** 发起截屏，**在截图上直接标注文字问题**，将标注后的截图与问题作为一次输入交给后端；回答完成后通知用户，再次按 F1 在全屏半透明回答层中从开头阅读，可滚动查看全文，再按 F1 关闭。

**本工具不是聊天客户端，不管理 Agent 会话。** F1 截屏与图上标注只是输入手段，回答输出通过后端获取：

- 接入 **Codex CLI** 时：会话、上下文与历史由 Codex CLI 自己管理。工具只负责把本次截图问题交给 CLI，并从 CLI 获取输出与历史。
- 接入 **API Key** 时：每次请求相互独立，不携带之前的会话，之前的上下文会丢失。

## 2. 目标与非目标

### 2.1 目标

- G1：按下 F1 到出现可框选的遮罩不超过 1 秒（P95）。
- G2：从发起截图到发送不超过三次核心操作：F1、在图上标注问题、发送；查看回答固定为一次 F1。
- G3：v1 至少支持两类后端：本地 `codex` CLI、OpenAI 兼容的 Chat Completions API。
- G4：支持在后台设置中配置 API Base URL、模型与 API Key，Key 不以明文落盘。
- G5：截图默认仅保存在内存或临时目录，请求结束后清理。
- G6：回答以全屏半透明层展示，不遮挡用户对后方内容的视觉感知，且无需切换应用即可阅读。
- G7：回答完成时主动通知用户，用户不会因等待而错过结果。
- G8：应用自身不管理 Agent 会话、不拼接上下文、不持久化问答历史；CLI 模式由 CLI 管理会话，API 模式固定单轮无上文。
- G9：用户可在设置中选择自己的截图热键；冲突的快捷键必须被明确拒绝，不能保存或生效。

### 2.2 非目标（v1 不做）

- 不实现 Agent 会话管理、上下文拼接、会话数据库或跨重启恢复。
- 不做多轮聊天界面；即使 CLI 自身保留上下文，工具每次也只做“一次截图输入 → 一次输出展示”。
- 不做完整 RPA 或自动点击执行。
- 不做 OCR 全文检索、截图资产管理或云同步。
- 不做账号体系、团队协作、多端同步。
- 不支持 macOS / Linux（v1 仅 Windows 10/11 x64）。
- 不做图片自由绘制编辑（箭头、马赛克等后续版本再评估），v1 仅做文字标注。

## 4. 功能需求

优先级定义：P0 为 v1 必须；P1 为 v1 应具备；P2 为后续增强。

### FR-1 常驻运行与 F1 全局热键（P0）

- 应用启动后驻留系统托盘，不占用任务栏主窗口。
- 默认截图热键为 **F1**，在应用未获得焦点时同样生效；用户可通过设置改为其他可用组合键（见 FR-13）。
- 截图热键是上下文相关热键，具体行为由 FR-12 的交互状态机决定，不能同时触发多个动作。
- 快捷键冲突时不得静默失败：设置中检测到冲突必须提示“已被占用，无法选择”并禁止保存；应用启动时若已保存的快捷键被占用，可临时启用受限监听回退并提示用户前往设置更换，回退仅识别目标热键，不拦截或记录其他按键。
- 同一时刻只允许一个截图流程或一次生成请求；重复触发时忽略并给出轻提示。
- 单实例运行：重复启动时唤醒已有实例，而不是再开一个进程。

### FR-2 截屏与框选（P0）

- 触发截图前，先隐藏本应用的回答层、通知浮层与设置窗口，避免把自身 UI 截入画面。
- 隐藏自身 UI 后冻结当前屏幕画面作为遮罩背景，并显示暗化遮罩。
- 支持鼠标拖拽框选任意矩形区域，选区尺寸至少 8×8 像素。
- 支持多显示器与不同缩放比例（100% / 125% / 150% / 200%）。
- 支持 Esc 取消整个截图流程，支持重新框选。
- 框选完成后显示选区边界、尺寸提示，并进入文字标注模式。

### FR-3 在截图上标注文字问题（P0）

- 框选完成后直接进入标注模式，无需额外弹窗或切换应用。
- 默认激活文字标注工具；在选区内点击即可放置文字输入框。
- 文本框支持多行输入与中文输入法；`Enter` 结束当前文本编辑，`Shift+Enter` 换行。
- 支持拖动文本框调整位置，支持编辑、删除与撤销；支持多个文字标注。
- 标注文字默认使用高对比颜色与清晰字号，并渲染在截图之上。
- 发送时执行两件事：
  1. 将标注文字**烧录进截图图像**，确保后端看到图上的问题。
  2. 将标注文字按阅读顺序拼接为本次问题文本，与图像一并发送。
- 本次问题文本只包含当前截图上的标注，**不拼接任何历史对话或之前的提问**。
- 发送方式：工具栏“发送提问”按钮或 `Ctrl+Enter`。
- 未填写任何标注文字时允许发送，默认问题为：“请分析这张截图中的内容，并给出可执行的建议。”
- 发送前展示本次目标后端及其会话模式，并可通过按钮或 `Tab` 切换后端；切换不丢失标注。
- 标注阶段按 `Esc`：正在编辑文本时退出编辑，否则取消整个截图流程。
- 标注阶段按 F1 不发起新截图，仅给出轻提示，避免误触丢失标注。

### FR-4 后端选择与路由（P0）

- 支持配置多个后端，设置一个默认后端，并记住上次使用的后端。
- 后端类型至少包括：
  - `cli`：本地命令行 Agent（内置 Codex CLI 预设，另支持自定义命令模板）。
  - `openai-compatible`：OpenAI 兼容的 Chat Completions 接口。
- 后端选择处必须明确显示会话模式：
  - CLI：`由 CLI 管理会话`。
  - API：`单轮，不保留上文`。
- 后端不可用时（命令不存在、未配置 Key），在发送前给出可操作的错误提示，而不是静默失败。
- 后端调用失败不影响应用常驻，可切换到其他后端重试。
- 应用不因切换后端而迁移或重建任何历史上下文。

### FR-5 本地 CLI 后端：会话由 CLI 管理（P0）

- 通过参数列表启动子进程，默认 `shell=False`，禁止将问题文本拼接进 shell 命令。
- 支持占位符 `{image}`、`{prompt}`；图片以临时文件路径传入，问题以独立参数传入。
- **会话、上下文与历史全部由 Codex CLI 自己管理**；应用不保存、不重放、不拼接之前的问答轮次。
- 首次请求由 CLI 建立新的会话；后续请求按 CLI 的“续接已有会话”语义调用，由 CLI 维护上下文。具体命令与参数由适配器配置，需在 M1 阶段核对 Codex CLI 当前版本的真实能力。
- 如果 CLI 无法续接已有会话（首次建立会话除外），必须提示用户，不得静默新建会话并让用户误以为上下文仍在。
- 回答输出从 CLI 的子进程输出中获取；完成通知与回答层展示均以该输出为准。
- “查看上次回答”等历史查看能力通过 CLI 的历史/输出命令获取，应用不另建历史库。
- 支持超时（默认 120 秒）与用户主动取消；取消时终止子进程及其子进程树。
- 不读取或改写用户的 Codex 登录态与全局配置。
- 传入的图片必须是已烧录标注的版本。
- 工具不提供额外的提示词工程或上下文注入，只传递本次截图与标注文本。

### FR-6 OpenAI 兼容 API 后端：单轮无上文（P1）

- 设置项包括：Base URL、模型名、API Key、超时时间。
- **API 模式为单轮请求**：每次只发送当前截图与当前问题，不发送任何之前的对话消息。
- 之前通过 API 产生的会话与上下文会丢失，这是预期行为；界面必须在选择该后端时明确提示“单轮，无上文”。
- 请求使用图片 + 文本的多模态消息；图片为已烧录标注的版本，优先压缩为长边不超过 2048 像素的 PNG/JPEG。
- 支持流式响应（SSE）；服务端不支持流式时回退为一次性返回。
- 请求失败时区分认证失败、限流、网络错误、服务端错误，并给出对应提示。
- API Key 仅从本地凭据存储读取，不写入配置文件与日志。
- API 模式不提供历史查询；“查看上次回答”只能展示当前进程中最近一次回答，若已发起新请求或应用重启则不可用，并明确提示原因。

### FR-7 全屏半透明回答视图（P0）

- 回答完成后，用户按 F1 打开回答视图（即用户所说的“对话界面”，状态规则见 FR-12）。
- 视图为**全屏大小**、无边框、置顶，不进入任务栏；多显示器时覆盖**鼠标所在屏幕**的完整工作区/屏幕区域。
- 视图背景为半透明，默认不透明度约 0.72（可配置范围 0.5–0.9），使用户仍能看到后方文字与界面轮廓。
- 回答文本覆盖在半透明背景之上，保持足够对比度；窗口需要接收滚动与按键事件，不做点击穿透。
- **每次打开都从回答的第一个字符/顶部开始展示**，滚动位置重置为 0。
- 支持以下滚动方式：
  - 鼠标滚轮向下/向上。
  - `↓` / `↑` 方向键。
  - `PageDown` / `PageUp`、空格键、`Home` / `End` 作为补充。
- 内容超过一屏时显示可滚动区域；内容不足一屏时不出现无意义滚动。
- 顶部或底部显示轻量提示：“回答完毕 · <当前热键> 关闭 · 滚轮/↓ 滚动”。
- 支持 Markdown 基础渲染（代码块、列表、行内代码）；代码块使用等宽字体。
- 按 F1 关闭回答视图；`Esc` 同样可关闭。关闭后标记该回答为已读。
- 回答视图只展示后端返回的输出，**不展示聊天记录、不展示用户历史提问、不提供会话侧栏**。
- 已读后需要再次查看时，通过托盘菜单“查看最近回答”重新打开，仍从顶部开始；内容来源见 FR-9。
- 回答视图渲染不得主动加载远程图片或外部资源。

### FR-8 设置与凭据管理（P1）

- 设置界面可管理：截图热键（默认 F1，选择与冲突校验见 FR-13）、默认后端、后端列表、超时、回答层不透明度、开机自启（默认关闭）。
- 设置中不提供“保存/恢复会话”选项，因为应用不管理会话。
- API Key 使用 Windows DPAPI 加密后存储，配置文件中仅保存引用标识。
- 修改热键、后端配置、回答层不透明度后即时生效或明确提示重启。
- 提供“测试连接”能力（CLI 检查可执行文件；API 发起轻量请求）。
- 支持恢复默认设置。

### FR-9 回答历史的来源（P1）

- **应用不建立本地问答历史库，不持久化截图、问题或回答。**
- CLI 模式：托盘“查看最近回答”通过 CLI 的历史/输出命令获取，展示在回答层中；若 CLI 无法提供历史，明确提示“无法从 CLI 获取历史”。
- API 模式：无历史。仅当当前进程内保留着最近一次回答时，可在尚未发起新请求前查看；发起新请求或应用重启后，明确提示“API 模式不保留历史会话”。
- 本地仅保存配置、加密凭据与运行日志；日志不得包含标注文字、问题正文、回答内容或截图。
- 临时截图文件在请求结束或取消后立即删除。

### FR-10 错误处理与取消（P0）

- 任一阶段按 `Esc` 可取消；取消后清理临时文件与子进程。
- 截图阶段取消不发送任何内容，不产生通知。
- 生成阶段取消后，不展示“回答完毕”，可展示“已取消”的轻提示。
- 生成失败时通知用户“回答失败”，按 F1 打开错误详情层，样式与回答视图一致，可从顶部阅读。
- CLI 会话续接失败时，提示“无法续接 CLI 会话”，不静默新建会话。
- API 模式请求失败或查看历史时，提示“单轮模式无历史上下文”，不误导用户。
- 应用崩溃或异常退出不应遗留大量临时截图。
- 网络不可用时，CLI 后端仍可正常使用。
- 错误信息使用用户可理解的中文，提供下一步操作建议；详细技术信息写入本地日志。

### FR-11 启动与更新（P1）

- 提供 Windows 安装包或免安装目录，启动无需管理员权限。
- M1 原型提供 PyInstaller 单文件便携版 `dist\ScreenToAgent.exe`，目标机无需安装 Python 或 PySide6。
- 打包脚本为项目根目录的 `build.bat`，图标为 `assets\ScreenToAgent.ico`。
- Codex CLI 不内嵌在 exe 中：目标机需已安装 `codex`（PATH 或 `%APPDATA%\npm\codex.cmd`），或在配置 `codex.executable` 中指定绝对路径；缺失时给出明确错误。
- 配置、日志与凭据仍写入 `%APPDATA%\ScreenToAgent\`，不写入 exe 所在目录。
- 未签名的 exe 可能触发 Windows SmartScreen；代码签名与安装器列入后续。
- 可选开机自启（默认关闭），通过用户级启动项实现。
- 版本升级保留配置与加密凭据（兼容旧配置结构）。
- v1 不要求自动更新。

### FR-12 回答完成通知与 F1 状态路由（P0）

- 请求完成后 1 秒内主动通知用户：标题“回答完毕”，正文“按当前截图热键查看 Agent 的回答”（实际显示用户配置的快捷键）。
- 通知方式优先使用系统托盘气泡；Windows 通知被专注助手抑制时，托盘图标仍需切换为“有待查看回答”状态。
- 生成失败时发送“回答失败”通知，并支持按当前截图热键查看错误详情。
- 通知点击可直接打开回答视图（P1）。
- 同一回答只通知一次，不重复打扰；取消的请求不发完成通知。
- 通知只提示“回答完毕”，不包含回答内容或会话信息。
- F1 行为必须严格遵循状态机，任何状态下都不得同时执行两个动作（下表以默认 F1 为例，实际使用当前配置的截图热键）：

| 当前状态 | 按 F1 的行为 |
| --- | --- |
| 空闲，无未读回答 | 开始截图与框选。 |
| 正在框选或标注 | 忽略并轻提示“请先完成或取消当前截图”，不得丢失标注。 |
| 正在生成回答 | 显示生成中状态层（含“取消”），不得发起新截图。 |
| 回答/错误已完成但未查看 | 打开全屏半透明回答视图，滚动位置置顶。 |
| 回答视图已打开 | 关闭视图，并标记本次回答为已读。 |
| 回答已读、视图已关闭 | 开始新的截图；CLI 模式下本次请求仍由 CLI 自行续接其会话；API 模式为全新单轮请求。 |

- 回答视图打开时，顶部/底部提示需说明“按当前热键关闭”，让用户明确再次按热键的后果。
- “查看最近回答”不改变会话归属：CLI 查 CLI 历史，API 只读当前进程内存。

### FR-13 快捷键设置与冲突校验（P0）

- 托盘菜单提供“设置…”入口，用户可打开设置对话框。
- 设置页显示当前截图热键；主键支持 F1–F12，可叠加 Ctrl / Alt / Shift / Win。
- 用户选择或修改热键时立即检测可用性：使用临时热键注册测试候选组合，不占用当前绑定。
- 候选快捷键不可用时，必须明确提示“已被其他程序占用，无法选择”，并禁用保存按钮；不得保存或应用该快捷键。
- 保存前再次检测冲突；冲突时阻止保存，现有配置文件与运行中的绑定均保持不变。
- 保存成功后写入 `%APPDATA%\ScreenToAgent\config.json` 的 `hotkey` 字段，并立即重新绑定，无需重启应用。
- 改键成功后，托盘菜单文案、托盘提示、通知正文、回答层与生成状态层中的热键提示必须同步更新。
- 若当前绑定来自启动时的受限监听回退（即快捷键存在冲突），设置页必须将其显示为冲突状态，用户需选择其他可用组合键后才能保存。
- 点击“取消”或关闭设置窗口不改变现有快捷键。
- 设置对话框打开期间忽略截图热键，避免误触发截图。

## 6. 交互流程

### 6.1 主流程

1. 用户在任意应用按 `F1`。
2. 应用隐藏自身回答层/通知，冻结屏幕并显示暗化遮罩。
3. 用户拖拽框选目标区域，松开鼠标。
4. 进入标注模式，用户在截图上点击并输入文字问题，可移动、编辑或删除标注。
5. 用户确认目标后端与会话模式，按 `Ctrl+Enter` 或点击“发送提问”。
6. 遮罩收起，应用进入生成状态；可取消。
7. 后端完成：
   - CLI 模式：输出来自 CLI，CLI 自己维护本次及之前的会话上下文。
   - API 模式：输出来自本次单轮请求，之前的 API 上下文不可恢复。
8. 应用通知“回答完毕，按 F1 查看”。
9. 用户按 `F1`，全屏半透明回答层出现，从回答开头展示。
10. 用户使用滚轮、`↓`、`PageDown` 等向下阅读全文。
11. 用户再次按 `F1`（或 `Esc`）关闭回答层；该回答标记为已读。
12. 用户再次按 `F1` 即开始新的截图提问；CLI 会话由 CLI 续接，API 则是独立的新请求。

### 6.2 会话归属

| 后端 | 会话/上下文归属 | 输出来源 | 历史查看 | 应用责任 |
| --- | --- | --- | --- | --- |
| Codex CLI | Codex CLI | CLI 子进程输出 | CLI 历史/输出命令 | 仅传递本次输入、取回输出、展示；不保存或拼接上下文 |
| API Key | 无（单轮） | 当前 HTTP 响应 | 无；仅当前进程内最近一次回答 | 不发送历史、不持久化、不承诺跨请求连续 |

### 6.3 F1 状态切换

```text
空闲 ──F1──> 框选 ──框选完成──> 标注 ──发送──> 生成中
  ^             │                  │                │
  │            Esc                Esc              完成/失败
  │             v                  v                v
  └────────── 空闲 <──F1关闭──── 回答视图 <──F1── 待查看
                                                   │
                                 托盘“查看最近回答” ┘
```

### 6.4 异常与取消

| 场景 | 期望行为 |
| --- | --- |
| 框选阶段按 Esc | 关闭遮罩，不发送任何内容。 |
| 标注阶段按 Esc | 正在编辑时退出编辑；否则取消整个截图流程。 |
| 选区过小 | 不进入标注，提示“选区太小”。 |
| 生成中按 F1 | 显示生成中状态，不发起新截图，可取消。 |
| 未填写标注直接发送 | 使用默认问题发送，图像仍按原样发送。 |
| CLI 可执行文件不存在 | 提示选择路径或安装命令，保留标注。 |
| CLI 无法续接会话 | 提示续接失败，不静默新建会话。 |
| API 未配置 Key | 提示前往设置，保留标注。 |
| API 模式查看历史 | 提示“单轮模式不保留历史”，仅在有最近内存结果时展示。 |
| 请求超时 | 停止请求并通知“回答失败”，F1 可查看详情。 |
| 用户点击取消 | 终止子进程/HTTP 请求，清理临时文件，不发完成通知。 |
| F1 热键冲突 | 设置页提示冲突，要求重新绑定。 |
| 系统通知被抑制 | 托盘图标显示待查看状态，F1 仍可打开回答。 |

## 7. 配置与数据模型（草案）

配置位置：`%APPDATA%\ScreenToAgent\config.json`；凭据位置：`%APPDATA%\ScreenToAgent\credentials.dat`（DPAPI 加密）。**不创建本地会话/问答历史数据库。**

```json
{
  "hotkey": "F1",
  "default_backend": "codex-cli",
  "last_backend": "codex-cli",
  "answer_overlay": {
    "opacity": 0.72,
    "monitor": "cursor"
  },
  "backends": [
    {
      "id": "codex-cli",
      "name": "Codex CLI（CLI 管理会话）",
      "type": "cli",
      "session_mode": "cli-managed",
      "command": ["codex", "exec", "-i", "{image}", "{prompt}"],
      "timeout_seconds": 120
    },
    {
      "id": "local-openai",
      "name": "本地 OpenAI 兼容服务（单轮，无上文）",
      "type": "openai-compatible",
      "session_mode": "stateless",
      "base_url": "http://127.0.0.1:11434/v1",
      "model": "qwen2.5-vl",
      "api_key_ref": "local-openai",
      "timeout_seconds": 120
    }
  ],
  "codex": {
    "executable": "codex",
    "sandbox": "read-only",
    "resume": true
  },
  "startup": {
    "launch_at_login": false
  }
}
```

说明：

- `hotkey` 默认 `F1`，可修改为其他可用组合键。
- `session_mode`：`cli-managed` 表示上下文由 CLI 管理；`stateless` 表示单轮、无上文。
- `command` 中仅允许 `{image}`、`{prompt}` 两个占位符；M1 原型先使用内置的 `codex exec` / `codex exec resume --last` 参数，`codex.resume` 控制后续请求是否续接。自定义命令模板与 CLI 历史命令在后续里程碑启用。
- `answer_overlay.opacity` 表示半透明层不透明度；`monitor: cursor` 表示覆盖鼠标所在屏幕。
- `api_key_ref` 指向凭据库条目，不包含密钥本身。
- 不配置本地历史路径，因为应用不保存问答历史。

## 8. 验收标准

- AC-1：在双显示器、缩放 150% 环境下，框选区域、标注坐标与最终发送的图像范围一致，误差为 0 像素。
- AC-2：按 F1 后 1 秒内出现遮罩；框选完成后 150ms 内可放置文字标注。
- AC-3：标注文字被烧录进发送的图像，同时作为问题文本传给后端；未填写时使用默认问题。
- AC-4：CLI 模式的请求使用 CLI 会话续接参数；应用不向 CLI 注入任何历史轮次，也不在本地保存问答历史。
- AC-5：API 模式的请求只包含当前截图与当前问题，不包含任何之前的消息；界面明确显示“单轮，不保留上文”。
- AC-6：发送后进入生成状态；后端完成后 1 秒内出现“回答完毕”通知。
- AC-7：通知后按当前截图热键（默认 F1），全屏半透明回答层覆盖鼠标所在屏幕，默认不透明度为 0.72±0.02，且从回答第一行开始展示。
- AC-8：回答层内滚轮向下、`↓`、`PageDown` 均可向下滚动；`↑`、`Home` 可回到前文/顶部。
- AC-9：再次按当前截图热键关闭回答层；下一次按该热键开始新截图。
- AC-10：CLI 模式下通过托盘“查看最近回答”时，内容来自 CLI 历史命令；CLI 无历史时给出明确提示。
- AC-11：API 模式下发起新请求或重启应用后，之前的回答不可查看，并提示“API 模式不保留历史会话”。
- AC-12：应用退出后不遗留会话数据库、问答记录或截图；本地仅有配置、加密凭据、脱敏日志。
- AC-13：生成中按当前截图热键只显示生成中状态，不产生新截图；取消后不出现“回答完毕”通知。
- AC-14：使用 CLI 后端时，问题与图片路径通过参数列表传入，进程环境不包含明文 API Key。
- AC-15：未配置 API Key 时选择 API 后端，发送前出现提示并可跳转设置，标注不丢失。
- AC-16：API Key 在 `config.json`、日志与应用运行目录中均不以明文出现。
- AC-17：截图前隐藏回答层与通知，抓取到的图像不包含本应用自身的回答视图。
- AC-18：任一阶段按 `Esc` 均可取消或关闭对应层，应用保持运行。
- AC-19：连续快速按当前截图热键不会产生多个遮罩、多个回答层或并发请求。
- AC-20：生成失败或 CLI 会话续接失败时出现“回答失败”通知，按 F1 可打开错误详情并从顶部阅读。
- AC-21：从托盘退出后无残留进程与临时截图文件。
- AC-22：F1 被其他程序占用时，应用仍能接收 F1（启用受限监听回退），且不记录或拦截其他按键；托盘给出明确提示。
- AC-23：用户可从托盘打开设置，选择 F1–F12 并叠加 Ctrl/Alt/Shift/Win；保存后配置写入 `config.json` 并立即生效，无需重启，托盘菜单与各层提示文字同步更新。
- AC-24：选择已被占用的快捷键时，设置页明确显示“已被占用，无法选择”，保存按钮不可用或保存被阻止，配置文件与运行中绑定均不改变。
- AC-25：在设置中点击取消或关闭窗口，不改变当前快捷键。
- AC-26：当前 F1 处于回退监听（存在冲突）时，设置页显示冲突状态；改选可用的 F5 后可以保存并立即绑定 F5。
- AC-27：设置对话框打开期间按截图热键不会触发截图。
- AC-28：双击 `dist\ScreenToAgent.exe` 可在未安装 Python 的 Windows 上启动托盘应用；配置与日志写入 `%APPDATA%\ScreenToAgent\`。
- AC-29：目标机未安装 Codex CLI 时，发送请求给出明确的“未找到 Codex CLI”提示，应用保持运行且可继续配置快捷键。

## 9. 风险与开放问题

| 编号 | 风险/问题 | 处理建议 |
| --- | --- | --- |
| R-1 | Codex CLI 的会话续接、历史查询参数与输出格式随版本变化 | 适配器隔离参数；配置化 `resume_args`/`history_command`；M1 核对真实 CLI。 |
| R-2 | CLI 会话可能被用户在终端中修改或清理，导致续接失败 | 明确提示续接失败，不静默新建会话；保留本次标注便于重试。 |
| R-3 | API 用户可能误以为有上文 | 后端选择与发送前明确标注“单轮，不保留上文”；错误与历史提示复用同一文案。 |
| R-4 | 混合 DPI 下 Qt 抓屏与标注坐标偏移 | M1 建立多屏/DPI 手测矩阵；按屏幕逐块抓取再合成。 |
| R-5 | F1 常被帮助菜单/游戏占用，全局注册可能失败 | 冲突检测与清晰提示；允许改绑；文档说明独占全屏场景限制。 |
| R-6 | 通用 CLI 模板可能被滥用为 shell 注入 | 仅参数列表启动，`shell=False`；若用户要求 shell，需显式警告。 |
| R-7 | 在线 API 隐私顾虑 | 发送前显示目标后端；默认本地；不记录请求正文。 |
| R-8 | 半透明全屏层可能影响后方文字辨识或自身文字可读性 | 默认 0.72 不透明度；提供 0.5–0.9 调节；正文高对比与最大行宽。 |
| R-9 | 全屏层覆盖范围与多显示器预期不一致 | v1 覆盖鼠标所在屏幕；是否覆盖全部屏幕列入开放问题。 |
| R-10 | 截屏把回答层一起截入 | 截图前隐藏自身 UI，并等待一帧后再冻结屏幕；加入自动化回归测试。 |
| Q-1 | Codex CLI 是否提供稳定的“续接最近会话”和“读取最近输出”命令？ | M1 验证；若没有，需评估仅传递单次输入、放弃历史查看，或改为让用户在 CLI 中自行查看。 |
| Q-2 | 是否需要在托盘中提供“新建 CLI 会话”入口？ | 应用不管理会话；若 CLI 本身支持新会话参数，可作为 P2 透传。 |
| Q-3 | API 模式未来是否支持多轮？ | v1 明确不支持；如需要，应作为新的需求另行评审。 |
| Q-4 | 回答层应覆盖鼠标所在屏幕还是所有屏幕？ | v1 采用鼠标所在屏幕；根据试用反馈再评估全屏拼接。 |
| Q-5 | 通知被系统专注助手抑制时是否需要额外自定义提示？ | 先切换托盘图标状态；必要时增加自绘提示条。 |
